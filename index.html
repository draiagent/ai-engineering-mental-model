AI Engineering
BUILD 建構
Prompts — 定義意圖 ＋

Prompts 是整個心智模型的入口層，決定 Agent「知道自己要做什麼」。

  • System Prompt：設定角色與邊界規則，整段對話最穩定的指令層
  • Few-shot：給 2–3 個「輸入→理想輸出」範例，模仿風格與格式
  • Memory & Context：餵入歷史紀錄與情境資料，決定「當下記得什麼」
口訣：System Prompt 決定角色、Few-shot 決定風格、Memory & Context 決定情境。
Skills — 執行專業任務 ＋

Skills 是動手做事的執行層，讓 Agent 具備專業能力而非只會聊天。

  • Code Interpreter：寫程式、跑計算，把推理變成可執行運算
  • Data Analyst：清洗彙整表格資料，萃取可決策的洞察
  • Web Researcher：主動查詢外部即時資訊，補足知識缺口
Skills 不是越多越好，關鍵是對應到具體交付物，判斷「這個任務該用哪個工具」。
Plugins / MCPs — 連接外部世界 ＋

MCPs 打通 Agent 與外部真實世界的橋樑——沒有這一層，再會想也摸不到真實資料。

  • Files & Docs：讀寫本地或雲端文件
  • Databases & APIs：連接結構化資料庫、第三方服務
  • Tools & Services：呼叫外部工具完成特定任務
風險最高的一層：連上資料庫或金流代表 Agent 能「動」到真實資料，務必搭配 Guardrails。
ORCHESTRATE 協調
Execution Patterns — 精煉決策 ＋

決定 Agent 執行任務時走的路徑結構，難度隨結構複雜度遞增。

  • Loop：反覆「嘗試→檢查→修正」，直到結果達標
  • Workflow：固定順序的步驟鏈，一步接一步線性執行
  • Graph Engineering：步驟間有分支、並行、依賴關係的網狀結構
Loop 把一件事做對，Workflow 把一連串事做順，Graph 把多條互相牽動的線同時理順。
Agent Teams — 團隊協作 ＋

不再單一 Agent 從頭做到尾，而是拆分角色分工，各司其職再彙整成果。

  • Planner：拆解總目標成子任務，決定先後順序與分派
  • Worker：專注把單一子任務做到位
  • Reviewer：檢視產出是否合格，決定過關或打回重做
分工有章法、品質有把關，才是真正的 Agent Teams，而非單純多開幾個 Agent。
Guardrails & Memory — 安全把關 ＋

協調層的最後一道防線，確保系統跑得快、跑得對，也不失控、不失憶。

  • Rules & Policies：設定不能碰的紅線與必須遵守的規範
  • RAG & Memory：檢索外部知識庫佐證，避免憑印象瞎編
  • State Management：追蹤任務進度，避免多步驟任務跑到一半失憶
事前防呆、事中查證、過程追蹤——三層遞進的把關邏輯。
